01What it is

Every tool call an AI agent proposes passes through one deterministic policy check, written in plain Python with no model in the loop. It returns ALLOW, DENY or REQUIRE_APPROVAL, and a tool runs only under a single-use grant bound to that exact call. We assume the most gullible model possible, and the tools stay safe anyway. The model is never the security boundary.

02What it does

Guards real tools

  • MCP proxy wraps every stdio server; only allowed calls get through
  • Claude Code hook: DENY blocks, APPROVAL becomes Claude's own ask prompt
  • Tool manifests pinned by HMAC, so a "rug pull" is withheld
  • Blocked real Claude Code from rm -rf ./* and cat .env, even with permissions bypassed

Mail securityNEW

  • Scans the email your agent reads: look-alike domains, Reply-To mismatch, shorteners, AI-directed instructions
  • An address copied from a phish cannot receive your data
  • High-risk mail triggers a phone alert call (Bolna voice agent)

Live consoleNEW

  • provenant dashboard: every decision, live, from the audit chain
  • Real traffic only; demo runs are labelled and never counted
  • Held calls approved only at a terminal, never in the browser
  • Gated MCP tool server: check, redeem grant, execute

What we have not proven yet

  • Paraphrase: provenance is value-based, so a reworded address can slip that one rule; the others still apply.
  • Shell: analysis is pattern-based; writing a script, then running it, is judged by the run command.
  • Remote MCP: only local stdio servers are proxied today.
  • Field tests: phone approval of held calls and the Windows one-liner have not run on real infrastructure yet.

Passing 225 cases is evidence for those cases, not proof that no bypass exists.
